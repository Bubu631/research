# Subsequent balanced-continuation digits protocol

This protocol is fixed before executing the balanced-continuation experiment. It was designed after completing and reviewing the original selective-continuation study, whose update trained on digits 0–4 and reduced overall reporting accuracy. It addresses that limitation with a second training path. It is not a preregistration of the project or a fresh confirmatory study. All five outcomes will be retained without outcome-based tuning.

The only training-path change is to continue on all 718 training examples (all ten classes), instead of the subset of training digits 0–4. Both paths use 24 continuation epochs; the balanced path therefore takes approximately twice as many mini-batch updates. This is an additional balanced-training path, not a compute-matched causal isolation of class coverage. The continuation optimizer restarts its momentum buffers at zero, as in the original implementation.

All other choices are identical to the first protocol: seeds 1701–1705; scikit-learn digits with pixels divided by 16; the same stratified 718/359/360/360 training/development/certification/reporting partitions; a 64–48–10 ReLU MLP; 12 incumbent-training epochs; mini-batch size 128; momentum SGD with learning rate 0.15 and momentum 0.9. Each seed deterministically retrains its incumbent from the original random stream, then continues from that exact checkpoint. The executed script verifies the incumbent arrays and split indices against the archived first-study checkpoints before evaluating the balanced update.

The development objective still weights each class 0–4 at 0.16 and each class 5–9 at 0.04. Both scalar and two-affine-block searches use 121 candidates; the tolerance is 0.03 per class. Feasibility, tie rules, the final development-only choice between proposal families, the paired Hoeffding gate at alpha 0.05, and exact incumbent fallback are unchanged. No certification or reporting outcome changes any of those choices. Every model's reporting overall accuracy, weighted accuracy, and class accuracy is saved, along with the original counts, all candidate development scores, checkpoints, losses, and all gate outcomes.

The certification and reporting partitions overlap the completed original study exactly within each seed; repeated seeds also reuse the same underlying dataset. This later study is descriptive. We do not combine its reused holdout outcomes with the original experiment to claim a fresh confirmatory real-world certificate, global error control across these two studies, or a new independent confidence interval. The mathematical gate is executed unchanged to show the pipeline's behavior. A future confirmatory deployment test would require a new independent sample or an appropriate sequential procedure. Seed standard deviations are descriptive.

Before training starts, the runner copies its executed source, the imported helper, and this protocol into the result directory and writes their SHA-256 hashes, software versions, dataset hash, configuration, and UTC start time to an in-progress manifest. The finished manifest adds every output hash and the completed outcome summaries. The comparison table includes both paths and every seed; no unfavorable result is discarded. This remains a small public MLP study, not a translation or foundation-model evaluation.

Command from `research_release`: `../.venv/bin/python experiments/digits_balanced.py`.
