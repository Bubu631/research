# Reproducing the research

This is a collection of four research directions, with a preserved predecessor for the wellbeing study. The projects retain separate environments and experiment manifests. Use each project's README for its full protocol, hardware requirements, seeds, and interpretation.

## Download and inspect

```bash
git clone https://github.com/Bubu631/research.git
cd research
```

The clone contains manuscripts, code, derived data, numerical results, and provenance. The eight additional per-record vocabulary-gradient arrays for edit localization are distributed in a release asset. Original dataset download caches, model weights, private notes, and local Python environments are excluded.

The [artifact index](ARTIFACTS.md) links individual PDFs, compilable source ZIPs, complete project bundles, workbooks, and the additional evidence archive. The original project ZIPs preserve the delivered research snapshot; the Git repository supplies the updated English navigation. Original experiment manifests are not rewritten to imply that an old run happened after GitHub publication.

## Restore the edit-localization gradient evidence

From the root of the cloned collection:

```bash
curl -fL -o public_gradient_evidence.zip \
  https://github.com/Bubu631/research/releases/download/v1.0.0/public_gradient_evidence.zip
```

Verify the downloaded archive against `release_metadata/SHA256SUMS.txt` before extraction:

```bash
python - <<'PY'
import hashlib
from pathlib import Path
name = 'public_gradient_evidence.zip'
entries = dict(line.split(maxsplit=1)[::-1] for line in
               Path('release_metadata/SHA256SUMS.txt').read_text().splitlines())
with open(name, 'rb') as stream:
    digest = hashlib.sha256()
    for block in iter(lambda: stream.read(1024 * 1024), b''):
        digest.update(block)
assert digest.hexdigest() == entries[name], 'Checksum mismatch'
print('Checksum verified')
PY
unzip public_gradient_evidence.zip
```

The archive paths start with `research_release/`, matching the collection. It adds eight arrays; it does not replace the source code or README files. To rebuild those arrays instead, follow `make reproduce-public` in [the first two projects' README](research_release/README.md).

The native mean-gradient bank is a separate, much larger cache regenerated by `make reproduce-full`. Its recorded Gram matrix and provenance are already included and support the reported norm-curve checks without committing the cache.

## Environments and checks

Create a separate virtual environment for the chosen project. The recorded manifests identify the environment actually used for each study; they take precedence over assuming that every run used the same interpreter. Full reproduction is more expensive than the checks below and can require public downloads.

| Project directory | Dependency entry point | Initial checks |
|---|---|---|
| `research_release` | `requirements-core.txt`; add `requirements-models.txt` for pretrained-model studies | `make test`; `python experiments/verify_artifact_integrity.py` |
| `nhs_aisi_research` | `requirements.txt` | `make verify` |
| `nhs_wellbeing_research` | `requirements.txt`; extra source-document tooling in `data_tools/requirements-data.txt` | `make checks PYTHON=python` |
| `agent_reliability_research` | `requirements.txt`; its README also explains core-only checks | `PYTHONPATH=. python -m unittest discover -s tests -v` |

Example for the first two papers:

```bash
cd research_release
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-core.txt
make test
python experiments/verify_artifact_integrity.py
```

The compact integrity check explicitly permits the eight absent large arrays. After restoring them, use `python experiments/verify_artifact_integrity.py --require-large` and the documented public-geometry checks. Model-dependent tests may skip if their dependencies are not installed; a skipped test does not establish that the corresponding model experiment was executed.

Verification scripts in some projects write audit reports. Full experimental commands overwrite their default result paths unless an output override is documented. Work in a separate clone or copy to preserve the released records, and compare rerun outputs to those records.

## Build the manuscripts

Install a TeX distribution providing `latexmk`, pdfLaTeX, and BibTeX. Run the following from the indicated project directory:

| Project directory | Command |
|---|---|
| `research_release` | `make papers` |
| `nhs_aisi_research` | `make paper` |
| `nhs_wellbeing_research` | `make latex` |
| `agent_reliability_research` | `cd paper && latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex` |

The release source ZIPs are self-contained manuscript source packages. Extract each into its own directory and use its supplied top-level TeX file. The named-author NHS source archive uses `main.tex`, while the repository keeps that entry point as `paper/full.tex`.

## Interpret a successful reproduction

A successful check supports the calculation or artifact it tests. It does not turn a constructed experiment into an observed deployment, recover unknown real selection propensities, or establish independent scientific review. Keep the fixed-checkpoint diagnostics, controlled simulations, public-data replays, and proposed future training studies distinct when citing these results.

For source attribution and rights, use [DATA_AND_RIGHTS.md](DATA_AND_RIGHTS.md) and the linked per-project manifests.
