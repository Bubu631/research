# SWE-Gym trajectory data protocol

Frozen before the full local data download and outcome inspection on 2026-09-12.

This is an offline, finite-population diagnostic. Historical executions provide the labels. We do not execute repository code, recreate containers, claim current-policy sampling, or infer wall-clock savings from label counts.

- Source: `SWE-Gym/OpenHands-Sampled-Trajectories`, revision `baf3a4e4bff514d48ddc08a93a2ade5c126212c7`, the three `train.raw` Parquet shards enumerated by the official Hugging Face API. Expected total download: 301,095,609 bytes. Record each exact URL, SHA-256, and access time.
- The official card exposes no explicit dataset licence field. Record this absence; do not equate a repository code licence with permission to redistribute all trajectory content or underlying repository code. Raw data remain local cache material.
- Define exact duplicates by SHA-256 of canonical JSON containing `messages` and `test_result.git_patch`. Retain the earliest source row, record all duplicate mappings, and exclude any label-conflicting duplicate identity from analysis. Preserve records with evaluation errors and empty patches in the audit; primary groups exclude evaluation errors, failed patch application, and test timeouts because those do not establish a valid pass/fail verdict. Empty generations remain legitimate failures when no other evaluator error is present.
- A task is `instance_id`. Assign it once by SHA-256 of `swe-gym-audit-v1|instance_id`: first eight hex digits modulo 100; 0–59 train, 60–79 calibration, 80–99 heldout. No outcome stratification. All trajectories of a task share a split.
- A logging configuration is `run_id` with only a terminal `_run_N` or `_runN` replicate suffix removed. Keep the remaining model, prompt, temperature, iteration-limit and configuration text intact. Also require the same canonical initial system/user prompt hash within a group. Do not label different logging configurations as an on-policy group.
- Within each task/configuration/initial-prompt block, sort unique eligible records by content hash and partition into non-overlapping groups of 4 or 8, separately for each requested group size. Retain every complete group, including all-zero and all-one groups. Discard only the final incomplete block. Report mixed-label counts descriptively, never select the primary population on mixedness.
- Record assistant-turn count, role counts, character lengths and UTF-8 byte lengths. These are not tokenizer lengths. Token counts require an explicitly pinned tokenizer and will be added separately if available.
- A proposed cheap feature baseline uses only trajectory `messages`: log-transformed role/character/tool-call counts, agent-visible terminal test command counts, and aggregate passed/failed/error text counts. Neither `resolved`, `test_result`, final patch, instance identity, nor run/model identity enters the feature vector. Terminal text is agent-visible feedback, not necessarily a standard public-test split. We do not treat historical tool results as fresh verification queries.
- Fit a fixed `StandardScaler` + L2 `LogisticRegression(C=1, max_iter=2000, solver=lbfgs)` on train tasks only. No hyperparameter selection from heldout labels. The calibration split is reserved for later audit-allocation tuning; report uncalibrated scores on all splits. Save selected feature names, coefficients, and prediction rows. AUC, Brier score and log loss assess the proxy, not the proposed audit estimator.
- Test-output timing strings, if present, are labelled as textual runner-reported timing. They are not a complete rollout/verifier cost log; container setup, scheduling and unreported test stages remain unknown.

Any departures must be recorded explicitly before interpreting downstream results.

## Availability-driven amendment: historical heterogeneous groups

After the initial parse, strict logging-configuration groups had at most two records and therefore zero G=4/G=8 groups. On 2026-09-12 the study scope was explicitly amended to add a separate **heterogeneous historical replay** population. The initial protocol, script, strict-group summary and proxy coefficients are preserved in `data/swe_gym/provenance/initial_strict_run/`. The original strict empty-group outputs remain in the processed directory.

For the added population, retain the same task split, valid-verdict exclusions, message-plus-patch deduplication and initial-prompt hash. Group within task and initial prompt, allowing different logging models, temperatures and iteration caps. Sort by content hash and partition into non-overlapping groups of 4 or 8. Record every member's full `run_id` and logging configuration. Do not select groups on reward mixedness or proxy performance. Save these only as `heterogeneous_groups_g4.jsonl` and `heterogeneous_groups_g8.jsonl`.

These groups define a fixed empirical surrogate update, not an on-policy sample from a common distribution. A later pinned Qwen model may evaluate gradients on these archived actions without being their generating policy. No behavior-policy importance correction is claimed. Full-group audit remains the comparator for this same empirical target, and the original impossibility/estimator calculations do not by themselves imply online learning performance.

One parser correction was also made: the actual filenames use a hyphen before the terminal `run_1`, so the replicate-suffix regular expression was expanded from an underscore-only separator to `[-_]run_?\d+$`. This changes descriptive configuration strings only; the strict block membership, zero group counts, features, splits and numerical proxy predictions are unchanged. The amendment was driven by data availability, not by estimator outcomes, which had not been computed on these groups.
